## Implemented

- Actor-scoped idempotent submission, transactional job/event/outbox creation, ordered persisted SSE replay, exact int64 cursors, ownership/session checks and explicit history gaps.
- Short PostgreSQL queue claims, monotonically increasing orchestration fences, 30-second leases and five-second heartbeats. Enqueue and publication validate the current job/epoch. Environment configuration and database dispatch flags both gate execution; restore and maintenance prevent ordinary new work. Only the designated backup job can recover its own maintenance window.
- Global/profile admission, per-machine operation admission, provider pool and exact-model permits, queue bounds and exclusive model-management permits. Unknown operations and uncertain provider requests retain reservations independently of worker leases.
- Actual enrolled signed RPC integration for supervised commands, file tools and trusted saved-action controls. There is no control-plane shell fallback. Before/after checkpoints surround potentially mutating commands, including verification commands. Missing identities or unsupported policy combinations fail explicitly.
- Persisted autonomous model/tool loop: immutable provider/profile/context snapshots, full structured-call validation, stable tool and operation IDs, persisted model/tool boundaries, bounded context/output/step/time/token handling, checkpoint/artifact provenance and actual verification records. Complete identifiable invalid calls are retained as rejected, non-executed tool results for bounded corrective feedback. Incomplete or ambiguous provider streams are never executed or automatically replayed.
- File tools list/read/conditional write/exact replacement patch, actual file-hash verification, machine observations, artifact retention and saved actions. Deterministic read/missing-file errors become recorded tool feedback; ambiguous mutations stay protected. Final verification uses the latest observation for each stable file/command identity while preserving earlier evidence. Failed final verification now also retains its computed result in the job row.
- Current and captured grants/profiles are intersected before fresh tools and each fresh inference, including current grant expiry/revocation, secret references, identity/model choices, configured budgets and remote-provider rules. Restrictive native networking and command-generated-file limits are rejected when this runtime cannot prove enforcement; file-tool size limits are enforced directly.
- Frozen retained attachment hashes/metadata, image capability checks and explicit text/image context delivery. Conversation rename/archive/recoverable deletion/restoration, stop requests, linked retry/continue attempts and original transcript preservation are implemented.
- Explicit reconciliation first locks/fences the job and makes it nonclaimable, then queries original host ledgers through narrow recovery reads. Only proven terminal operations or atomically proven non-delivery release the writer. Provider reservation recovery is separately labelled operator attestation with recorded evidence; it is not presented as machine-confirmed cancellation.
- Final delivery-authority integration passes persisted job/workspace/grant/tool guards to the broker for command/control/file calls and scoped job file reads/checkpoints/export. Controller receipts explicitly proving zero delivery/no effects produce a known cancelled/rejected operation; stale workers cannot rewrite operation metadata after fencing.
- Worker startup wires provider jobs, remote/capability probes, telemetry retention, project export, saved actions and the fixed trusted backup handler. Health timestamps update only after successful database queries.

The implementation is under `apps/worker/src/` and `apps/api/src/modules/jobs/`. Main integration is `apps/worker/src/main.ts`; transport and host protocol remain owned by their respective packages/agents.

### Cumulative output unit (next coherent source cut after CORE17)

A fenced job-event ledger now accounts producer content across every inference, primary command, configured verifier, and optional retained terminal transcript. UTF-8 text uses actual encoded bytes; binary terminal output uses actual decoded bytes. Complete parsed tool proposal JSON is accepted or rejected whole before any tool step is persisted or executed. Text/log retention can stop on a valid UTF-8 boundary with explicit limited metadata. Job detail exposes output_budget {limit_bytes,retained_bytes,received_bytes,limited_events,scope}.

This is a cumulative retained-producer-content budget, not a promise that an upstream provider spent no extra tokens or a host emitted no additional bytes. Metadata, repeated evidence representations, tool read results, input context, transient live terminal replay, provider-internal reasoning and checkpoint/artifact blob storage are separate bounded surfaces. Producer content is charged once by stable inference/delta, complete-call set, operation/log sequence or terminal spool range. Publication and cursors commit with usage in one fenced transaction. Legacy persisted producer events seed accounting on recovery. Replayed producer IDs cannot recharge the budget or change content silently.

A provider stream stopped by the local output boundary remains uncertain until independent stop evidence; its permit and unresolved writer are retained. Existing host work is reconciled/cancelled by its original operation ID, while fresh commands or inferences cannot start with no remaining output budget. Provider reservation acquisition/release/uncertain changes also require the current job lease/fence, preventing an old worker from releasing a replacement inference's reservation.

Direct write_file/apply_patch operations reserve cumulative full prepared-file bytes before dispatch, including historical durable operations. Replacing a file again consumes another full prepared-content reservation. Failed or never-delivered prepared writes conservatively retain that reservation within the same job. Replay of the same operation does not charge again. This bounds prepared direct-file content, not arbitrary process filesystem writes: a command requiring max_generated_file_bytes is rejected with command_generated_file_limit_runtime_unsupported until the host runtime can enforce that hard total-write limit.
