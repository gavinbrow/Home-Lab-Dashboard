# Shared implementation contract v1

All wire/domain keys use snake_case; schema_version is 1. Import domain types and Zod runtime schemas from `@homelab/contracts` (packages/contracts/src/index.ts). Import `authorize`, `resolveRunContext` from `@homelab/policy`. Package dependencies use exact `0.1.0` workspace versions. Node runs TypeScript through tsx; ESM relative imports use `.js`.

Each API owner exports default `async function register(app: FastifyInstance, context: ApiContext): Promise<void>` from `apps/api/src/modules/TRACK/index.ts`. Import `ApiContext` from `../../core/context.js`. Composition mounts the module inside authenticated `/api/v1`; define local routes `/machines`, `/jobs`, `/projects`, `/providers`, `/terminals`, `/desktop-sessions`, `/actions`. Do not add another prefix. app request.actor is non-null after auth; sessionId is a database session UUID. Public agent bootstrap/mTLS endpoints need separate composition, coordinate with platform.

ApiContext is authoritative in apps/api/src/core/context.ts: `db: pg.Pool`, `secrets.put(ownerId,name,value): Promise<id>` and `get(ownerId,id):Promise<plaintext>` (server only); `policy` is authorize; `audit(actorId,action,target,outcome,details?):Promise<void>`; config origin/cookieSecure/artifactRoot/dispatchEnabled/restoreMode. No request/response credential logging.

API responses: list `{items:[]}`; object direct; failures `{error:{code,message,details?},request_id?}`. Unconfigured resources return empty/explicit capability failure, never fixtures. Mutations require Origin equal APP_ORIGIN and `X-CSRF-Token` matching session token. Auth routes: POST /api/v1/auth/bootstrap {email,password,token}; POST /api/v1/auth/login {email,password}; GET /api/v1/auth/session; POST /api/v1/auth/logout. Login/session returns {actor,csrf_token}; cookie homelab_session, HttpOnly, Secure in production, SameSite strict.

Policy calls require both immutable captured grant and current persisted grant. `authorize({actor,tool,machine_id?,workspace_id?,profile_id?,grant,current_grant})` returns `{allowed,code,reason,policy_revision}`. Missing grant denies tool operations. Entity CRUD separately checks SQL owner_id=request.actor.id. Profile revisions cannot expand run scope. resolveRunContext(context,workspace|null) refuses host/revision/generation mismatches.

Canonical types: Actor, RunContext/RunContextSchema, Limits/LimitsSchema, Machine, Capability/CapabilitySchema, Workspace, Environment, Artifact, Checkpoint/CheckpointEntry, PolicyGrant, PolicyRequest/Decision, JobState/JobStateSchema, JobEvent, OperationRequest/Receipt/State, JsonValue, ApiError. Request hash canonicalization must recursively sort object keys, JSON-encode, SHA-256, excluding request_hash/fence/dispatch_epoch. Escape U+2028/U+2029 as backslash-u sequences to match Go JSON encoding. No automatic uncertain-command replay. Host receipt states include outcome_unknown and use monotonic host_sequence. Ledger and workspace lock ownership survive orchestration lease expiry.

Root dependency installation/lockfile and db/migrations are platform-owned. Send additive dependency/schema requests. Each module may add module-local unit tests; validation owns tests/integration. Machine schemas, table baseline and module registration will be integrated by platform. SQL names/columns are canonical in db/migrations, consult before using.


## Resumed integration contracts

`@homelab/contracts` exports `ExecutionContextSchema` / `ExecutionContext`: all execution, profile, workspace, environment, instruction revision, policy and limit fields from RunContext, with provider/model fields omitted. Model-free jobs keep `jobs.context = null` and capture `payload.execution_context`; no synthetic provider selection. OperationRequest optionally carries `saved_action:{action_id,revision,definition_hash}` in the semantic request hash; fixed saved commands require both actions.run and run_command at backend and host.

Migration011 provides terminal_sessions and single-use terminal_tickets, plus jobs.last_heartbeat_at. Workspace terminal jobs own the writer lock through confirmed process termination; both workspace.terminal and run_command are required. Broker permits `/v1/terminals` and exact UUID terminal safety cancellation, with ordinary execution admission retained.

Migration012 provides blob_objects, blob_references, upload_sessions/upload_chunks and storage_recovery_reviews. Reference publication and GC use `pg_advisory_xact_lock(hashtextextended('homelab-blob:'||sha256,0))`; publication to non-live blobs fails. Historical objects can have unknown size0 until bytes are verified. Metadata triggers retain checkpoint/artifact/attachment/message/log/change references, including tombstones. Backup manifests publish only explicit `blob_refs:[{sha256}]`; external archive hashes are not central blob references.

`npm run db:provision` requires DATABASE_ADMIN_URL_FILE, EXPECTED_DATABASE, APP_DB_PASSWORD_FILE and MIGRATION_DB_PASSWORD_FILE; APP_DB_ROLE defaults homelab_app and MIGRATION_DB_ROLE defaults homelab_migrator. It changes only the designated database/public application objects, rejects role ownership in other databases and preexisting role memberships. `npm run db:migrate` prefers MIGRATION_DATABASE_URL and uses APP_DB_ROLE to protect migration metadata. Runtime DATABASE_URL is the DML account.


Terminal delivery staging (migration017): fixed `/v1/terminals` RPCs have a 30-second delivery TTL. Pending request bytes are erased after host acknowledgement; response bytes are erased after broker consumer receipt. Expiry cleanup runs every second in a healthy API/worker and resumes after downtime; this is logical delivery retention, not a forensic/WAL erasure guarantee. Migration018 removes enumerable terminal request/response digests and original authorization signatures, retaining ID/status/delivery-only tombstones; original process-operation hashes remain separate. Request fingerprints disappear on host acknowledgement; response fingerprints disappear with consumed/expired bytes. a consumed/expired replay receives410 `terminal_delivery_expired` and is never re-executed. Backup cuts call `broker.expireTerminalPayloads(true)` after terminal/job drain and repeat until zero, erasing closed terminal staging before dump. Transcript opt-in is separate retained job output.

Workspace terminal browser RPCs include internal `jobGuard.terminal_client_id`; first delivery rechecks the current browser session and current controller for reads and writes. Safety cancellation remains available for process drain after logout. Agent RPC envelopes and inner OperationRequest may carry `machine_identity_generation`; both are signed/hashed and host-pinned. Initial trusted scope/job maps may not be silently refreshed after installation replacement.
