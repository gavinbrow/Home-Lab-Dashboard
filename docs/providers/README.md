# Provider integration

Status: adapter fixture tests pass, and an actual isolated CPU-only Ollama 0.40.6 / Qwen3 0.6B component check passes discovery, native streaming, a structured tool/result round trip, JSON output, runtime state and unload. This is a newly created test environment, not the owner's homelab inventory or complete T16–T18 release acceptance. Actual Windows/Linux dashboard jobs, external provider compatibility and the remaining release scenarios still need their own evidence. The normal adapter suite uses local HTTP/HTTPS fixtures; it does not establish model reasoning quality.

Current resumed campaign: a separately selected Qwen2.5 1.5B model also passes seven actual provider checks and the actual persisted-worker/signed-Go file workflow. Its evidence and the original 0.6B failures are both retained; see `VERIFICATION.md`. The isolated provider remains running only for the validation track's long-job recovery checks.

The API stores provider revisions, private credential references, shared runtime pool IDs, exact model IDs and routing evidence separately from execution machine/workspace selections. Configure `config.allowed_addresses`, `config.allow_private_http` and `config.timeout_ms`. The URL may be the server root or `/v1`; no other path, URL credentials, query or fragment is accepted. DNS answers must all match enrolled IPs and the selected answer is pinned for connection. Redirects, metadata/link-local destinations, unspecified addresses and multicast are denied. TLS verification remains enabled. A bounded `config.private_ca_pem` bundle explicitly adds private CA trust for this provider; host identity and certificate verification remain enabled. CA private keys are rejected.

`@homelab/providers` exports `createProviderAdapter(snapshot, {resolveCredential})`. `streamChat` yields text followed by one `completed` event. Only complete structured calls whose arguments pass the offered JSON schema enter the dispatchable call array. A truncated stream never yields executable calls. The worker still checks current backend policy and persists tool decisions before dispatch. Code blocks remain text. Client abort does not prove provider termination.

The completed event separates schema-valid `toolCalls` from complete identifiable `rejectedToolCalls` (original ID/name/arguments, stable index and bounded schema error). Rejected calls are never dispatched; the worker may persist them as error results and request a correction under the existing step/time budgets. Malformed JSON, ambiguous identities and interrupted streams still fail. Provider `config.context_length` is captured into the immutable snapshot and supplied as native Ollama `num_ctx`; it never silently substitutes a model or discards schema requirements.

Generic compatible and vLLM adapters use `/v1/models` and `/v1/chat/completions`. Residency and external activity remain unknown. Ollama uses native catalog/chat/runtime routes, with explicit load/unload and streamed pull progress. LM Studio uses compatible inference plus documented native v1 catalog and management. Model capabilities reported by a catalog are claims; explicit smoke probes persist tested results for the configuration revision. User messages may contain bounded PNG/JPEG/WebP bytes. Explicit `image_input` smoke probes send two generated distinguishable solid-color PNGs; these establish only smoke compatibility. `cancellation` probes distinguish observed client stop from unconfirmed server stop and retain an uncertain reservation. Discovery performs no inference.

API routes under `/api/v1`:

- `GET/POST /providers`, `GET/PUT /providers/:id` (updates require the observed revision).
- `GET /models`, `GET /providers/:id/models`, `POST /providers/:id/models/manual`.
- `PUT /providers/:id/favorites` with exact `model_id` and boolean `favorite`.
- `POST /providers/:id/discover`, `/runtime`, `/capability-tests`, `/management`: require `idempotency_key`, return an accepted durable job ID. Probes additionally require `model_id` and one of `basic_chat`, `streaming`, `tools`, `structured_output`, `image_input`, `cancellation`. Management requires an explicit action and exact model/instance/download job ID.
- `POST /providers/:id/connection-tests` reports DNS, TCP, TLS, authentication and catalog independently without running inference. It also requires `idempotency_key` and uses the same frozen destination policy.
- `GET /provider-runtime-pools`, `PUT /provider-runtime-pools/:id` expose owner-scoped `name`, `max_concurrency`, and `max_queue`. Provider configuration carries `max_model_concurrency` (default one); the worker owns durable pool/model slots and bounded submission.
- `GET /providers/:id/activity` reports dashboard held/uncertain reservations and queued jobs for the shared pool, alongside explicit unknown external activity. A reservation is not advertised as proof the provider is currently generating. `GET /providers/:id/performance` returns the latest 100 persisted inference measurements with job/model identity and timestamps.

Provider creation accepts an input-only `credential`. Responses expose only `credential_configured`. Endpoint edits affect future jobs; job payloads freeze the provider snapshot. Compatible adapters do not silently fall back to a different provider/model. Owner-authorized creation/editing checks SQL resource ownership. Runtime aliases for the same origin share capacity; distinct hostnames/IP aliases must explicitly select the same runtime pool.

`executeProviderJob` is exported from `@homelab/providers/jobs`. The worker composes it with durable provider reservations, encrypted secret resolution and its lease/fence checks. Discovery/runtime requests can be repeated safely; inference and management persist a start boundary and refuse automatic replay after uncertain outcomes. Downloads retain progress and status, and interruption/cancellation stays unconfirmed if native server termination cannot be established. Chat/message persistence belongs to the worker's chat handler, not an HTTP connection.

Metrics use provider counts and native durations only. Ollama nanoseconds become seconds. Prompt throughput stays unavailable when cache counts are absent. SSE chunks are never tokens; time to first content and wall time are separate from native generation speed.

Run `npm test -w @homelab/providers` after the root workspace dependency installation. Root typechecking includes adapter, API and job integration source.

Images use `ChatMessage.images: [{mimeType,base64}]`; they are explicit attachment content, never provider-fetchable arbitrary URLs or remote filesystem paths. Limits are eight images per message, 8 MiB per image and 16 MiB per conversation request. JPEG/PNG/WebP signatures must match declared MIME. Compatible inference receives data-URI image content; native Ollama receives base64 image arrays. The API/worker attachment service remains responsible for ownership, upload storage and project remote-processing policy before supplying these bytes.

Management supports optional LM Studio `load_settings: {context_length,eval_batch_size,flash_attention}`. Native downloads produce durable `provider.download.progress` events. Confirmed download failure is a failed job; disconnects, unknown outcomes, and unconfirmed stop preserve reservations. Probes record exact configuration revision, probe version, requested/resolved model, discoverable server version and raw/normalized metrics. Complete invalid tool arguments record tested failure; interrupted streams remain uncertain and are not replayed.

New probes bind available model digest/variant and server version. Passive worker discovery refreshes those values before required-capability generation; the API and worker share `probeValidity`. A same-configuration model/server change makes historical passing evidence stale. The API returns `effective_state` and detailed `validity`, alongside the original immutable probe outcome. `config.observation_max_age_seconds` (default 300) controls catalog/runtime freshness labels; age never becomes a fabricated current observation. Servers that expose no identity metadata retain explicit unknown identity fields.

An explicitly selected native loaded instance keeps its inference ID. Its parent catalog identity and instance configuration fingerprint bind the probe; changing the selected configuration invalidates earlier passing evidence.

The PEM key/certificate under `packages/providers/test/fixtures/localhost-test-*` is a synthetic localhost-only test authority, never a deployment credential. HTTPS fixture tests prove explicit CA trust works and default trust rejects that authority. `packages/providers/test/live-check.ts` is an explicit loopback-only actual-provider component harness; it requires an endpoint, exact model ID and output evidence path and runs outside the normal fixture suite. Actual model evidence is separate from real homelab acceptance.

Actual isolated model evidence: `actual-provider-component-results.json` (seven passing component checks), `actual-fixture-inventory.json` (container/image identity and resource constraints), `actual-model-hashes.txt` (model blob/manifest SHA-256), `actual-cpu-source-manifest.json` (official source checksum and retained file hashes). The initial long UUID prompt checks failed; `actual-provider-first-attempt.json` preserves those failures. Using a shorter random nonce and a simple tool description passed without provider/model fallback. This illustrates the difference between protocol compatibility and broad reasoning reliability.
