# Actual command workflow diagnosis

Job `e815a839-1ac7-42fc-8c3b-7764c8ed07bb` selected the actual isolated Qwen2.5 1.5B model. It failed before any physical command. Its earlier successful file workflow remains separate evidence.

The [persisted request export](../acceptance/linux-sentinel-gen6-inference-requests.json) contains the actual six offered tool schemas and conversation, not a reconstructed prompt. `run_command` declares separate required `executable` and `args` fields, excludes extra properties, and describes both fields. The first completed response instead placed the executable inside `args`, omitting `executable`. Strict validation rejected it with `executed:false`. The next inference received the failed proposal, exact expected schema and corrective result; it asked the user to repair the arguments and stopped. No argument coercion or command dispatch occurred.

Actual provider prompt counts were 831 and 1050 tokens with 4096 configured context. Dedicated runner logs reported `truncated = 0` for both generations. The preserved [resource/log diagnostic](actual-gen6-resource-diagnostic.txt) records no OOM kills, a 2 GiB memory cap, 2 CPU limit and historical memory-pressure events. These facts support a model tool-format/recovery limitation for this task; they do not demonstrate context truncation. The model's full autonomous command workflow has not passed.

The pinned Ollama 0.40.6 [native request type](https://github.com/ollama/ollama/blob/v0.40.6/api/types.go) and [compatibility request implementation](https://github.com/ollama/ollama/blob/v0.40.6/openai/openai.go) have no `tool_choice` field. Current [unversioned compatibility documentation](https://docs.ollama.com/api/openai-compatibility) lists it, while the [native chat documentation](https://docs.ollama.com/api/chat) does not. This fixture cannot claim forced tool selection based on the unversioned page. No undocumented parameter has been added.

One possible explicit successor is [Qwen3 4B Q4_K_M](https://ollama.com/library/qwen3:4b), advertised as tool capable, approximately 2.5 GB and Apache-2.0. A proposed isolated 6 GiB memory cap, unchanged 2 CPU/no GPU and 4096 context leaves headroom for weights, KV cache and scratch allocations. This is an estimate, not a measured requirement or success claim. The diagnostic observed approximately 47 GB available inside WSL before any change. Its download would increase the dedicated model volume from approximately 1.51 GB to approximately 4.1 GB; full model digest and actual byte totals must be recorded after an explicitly authorized pull. No successor model was downloaded as part of this diagnosis.

A deterministic signed-Go command precursor can independently isolate durable command execution and recovery. Such a result cannot substitute for the required actual model-driven command workflow. No failed job should be replayed or silently moved to another model.

The coordinator subsequently approved exactly this separate Qwen3 4B test. The model was pulled with upstream SHA verification and independently hashed; [selection and actual limits](actual-qwen3-4b-selection.json), [catalog](actual-qwen3-4b-catalog.json), [model hashes](actual-qwen3-4b-model-hashes.txt) and [runtime sample](actual-qwen3-4b-runtime-sample.txt) retain the evidence. The dedicated model volume is 4,006,019,471 bytes. The local manifest is a wrapper containing the upstream manifest as a layer; its local-file hash is recorded separately from the verified upstream model digest. A bounded comparison reuses the exact six tools and initial prompt from the failed job without executing any proposed tool.

That first [4B comparison](actual-qwen3-4b-command-schema-result.json) completed with `finishReason:length`, 833 input tokens and 256 output tokens after 262.59 seconds. It generated reasoning prose without reaching a tool proposal. This is output-budget exhaustion, not a completed invalid call or evidence that tools are unsupported. Native [installed settings](actual-qwen3-4b-template-settings.json) expose `thinking.values:[true]`, so `think:false` cannot be claimed as a supported hard non-thinking switch for this exact installation. The [model author's soft `/no_think` control](https://qwenlm.github.io/blog/qwen3/#advanced-usages) may be explicitly tested in a new prompt, with its scope recorded.

The request also exposed a real transport defect: the original `AbortSignal.timeout`/`AbortSignal.any` path did not terminate a continuously active response body in this runtime. The first check exceeded its requested 180-second deadline and eventually stopped naturally at its 256-token limit. A local HTTP regression reproduced the defect with an 80 ms deadline and a continuously emitting body. Transport now owns an explicit timer and abort controller throughout the body lifetime and releases them on completion, cancellation or failure. Both the continuous-body deadline and caller abort while awaiting another chunk pass in the 25-test suite. This confirms local delivery termination; it does not claim an upstream inference has stopped. Interrupted production requests continue to retain uncertainty under worker reservation rules.

After the comparison, `/api/ps` was empty; fixture settings remain `OLLAMA_NUM_PARALLEL=1` and `OLLAMA_MAX_LOADED_MODELS=1`. No prior idle model needed unloading. [Post-check memory](actual-qwen3-4b-post-check-memory.txt) records approximately 19 MB anonymous memory and 3.09 GB file pages after the model unloaded. Active generation sampled 5.42 GiB excluding inactive file cache while cgroup current memory approached its 6 GiB cap; no OOM kill was observed. A future explicit resource increase must occur while idle and be recorded independently.

The approved follow-up [selection](actual-qwen3-4b-expanded-selection.json) used the same model digest, 8 GiB memory/swap, four CPUs, no GPU, 4096 context, 1024 output tokens and a 360-second streaming deadline with a 420-second harness bound. Available WSL memory exceeded 46 GB before the idle-only update. Native thinking was enabled because the installed model advertises only `true`; the user prompt explicitly appended the documented soft `/no_think` instruction. No hard non-thinking guarantee was made.

The [actual follow-up](actual-qwen3-4b-soft-command-schema-result.json) **passed** in 244.91 seconds: 836 input tokens, 838 output tokens, `finishReason:stop`, and exactly one validated `run_command` proposal with the required executable and exact four separate arguments. Zero tools executed in this check. Runner logs reported no truncation. Active runtime sampled 5.46 GiB excluding inactive file cache, with no new memory-pressure events or OOM kills. The exact installed model metadata identifies a `Thinking` finetune. This explains why a larger explicit output budget matters and why the previous 256-token result must remain classified as exhaustion, not unsupported tools. This result establishes a genuine structured proposal; the separate persisted model→signed-Go command/recovery workflow still requires its own acceptance evidence.

The subsequent actual job `5a43a51c-3e97-46ca-97d9-f6ba508e63d1` selected the same 4B model explicitly. Its [retained responses and tool results](../acceptance/actual-model-command-retained-responses.json) record a valid first proposal after 276.18 seconds (836 input/838 output tokens, `finishReason:stop`) and a physical 180-second command that returned exit code zero with both output paths and hashes. The second inference consumed the real command result and the unchanged six tool schemas. It had 1567 input tokens and exhausted all 1024 output tokens after 334.75 seconds, with `finishReason:length`, no visible content and no tool proposals. The [runner log](actual-4b-command-post-result-runner-log.txt) independently reports `truncated = 0`; total input/output was 2591 tokens inside the 4096 context. Native reasoning text was not retained, so its content cannot be inferred. No second-round schema rejection occurred. The worker then failed required verification rather than claiming those files had been independently verified or retained. This is generation-budget exhaustion before the required verification/artifact phase, not an unsupported tool contract, context truncation, or transport failure.

This closes the actual model command/verification/retention gate for that scoped Linux run; final independent host-off downloads and cleanup have separate owners. Earlier unsuccessful jobs and synthetic diagnostics remain preserved below.

One more 4B attempt with 2048 output tokens would fit that recorded input inside 4096 context, but at the measured 3.58 output tokens/second it could require approximately 615 seconds per round including prompt processing and a substantially longer deadline. The approved next diagnostic instead uses the already installed non-thinking Qwen2.5 1.5B with a concise task and the same six strict schemas. It is bounded to 180 seconds overall, seven rounds, one corrective response and 512 output tokens per round. All tool results are clearly synthetic; no host commands, workspace files or real artifacts execute. A passing diagnostic can justify a new explicit actual job after a coherent source cut; it cannot itself close the actual verification gate, replace a model inside a failed job, or replay the already accepted command.

The original evidence was not rewritten.

Its original global deadline had only 34.52 seconds remaining after CPU coordination. The stream was interrupted at that absolute deadline, and the [runner log](actual-qwen25-sequence-global-deadline.txt) confirms cancellation and idle slots. That correction is **inconclusive**, not a semantic model failure; the full correction response was never received.

After an explicit fresh CPU booking, one [new continuation against the retained first response](actual-qwen25-synthetic-sequence-fresh-continuation.json) completed in 36.16 seconds (1767 input/163 output tokens, `finishReason:stop`). It corrected the command to the exact executable and four arguments. However, all four file proposals still used `/workspace/project/...` despite explicit workspace-relative instructions. These proposals pass the current broad string schemas but violate the workspace file-path contract. The harness did not strip prefixes or execute them, and no final synthetic completion request followed an invalid correction. [Completion logs](actual-qwen25-sequence-fresh-completion.txt) show no truncation and idle CPU/slots. This is a concrete path-contract failure for this bounded synthetic sequence, not output-budget exhaustion or a broad claim of unsupported tools. There were zero host commands, workspace file changes or real retained artifacts across these probes. No new actual job is justified as a passing sequence from this evidence.
