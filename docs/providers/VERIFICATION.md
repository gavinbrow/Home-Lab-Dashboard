`local-test-results.txt` records 25 passing local fixture tests. These include real HTTPS, active-stream deadline and caller cancellation checks, not actual model inference tests. `actual-provider-component-results.json` separately records actual inference. Its `tool_call_round_trip` includes both provider responses and the exact harmless fixture call; the first response comes from an actual model, not a programmed completion fixture.

The first actual attempt used a long UUID and a more elaborate tool instruction. The small model failed that prompt despite working native protocol and JSON output; those failures remain in `actual-provider-first-attempt.json`. A shorter random nonce and plain tool description passed. The result proves this particular integration smoke test, not general tool-use reliability. Profiles must still require exact configuration-specific tested capabilities.

The larger actual agent tool set exposed additional model mistakes: a string `"null"` for an optional hash and `mimeType` where the declared key is `mime_type`. `actual-agent-tool-diagnostic.json` retains the fixture-only raw response. Validation was not weakened: complete identifiable invalid calls are separated as `rejectedToolCalls` with bounded schema errors and original arguments; they cannot enter the dispatchable `toolCalls` array. The worker can persist these rejected proposals and return error results for a bounded corrective inference. Incomplete streams, malformed JSON, missing identities and duplicate identities never become executable proposals.
