# Agent transport protocol v1

`@homelab/transport` owns the durable `AgentBroker` and canonical signing. API and worker call `broker.rpc(machineId,method,path,body?,{requestId?,timeoutMs?,expiresInMs?,ownerId?,signal?})`. IDs are durable UUIDs; a reused ID with changed semantic request conflicts. Retrying after a lost response uses the same ID. A timeout after delivery is unknown, not proof of failure. Host caches RPC receipt/result durably before reporting; pending mutating requests are never blindly replayed after an agent crash.

Agent TLS listener uses server key/cert and private CA. It requests client certificates and verifies socket.authorized plus DB machine/fingerprint/revocation for every non-bootstrap route. No forwarded identity header is trusted. Exact TLS-only bootstrap route POST `/agent/v1/enroll` accepts `{token,csr_pem,protocol_version:1}`. Server issues only the pending machine subject/URI identity; token is single-use and expires. Response includes certificate PEM, CA PEM and pinned dispatch public key/key ID. Private host key never leaves the host. Certificate rotation is authenticated by current identity; revocation denies future requests and active polling.

POST `/agent/v1/poll` body `{schema_version:1,machine_id,boot_id,max_requests:1}` returns `{requests:AgentRpcRequest[],server_time}`. Polling machine ID must equal TLS identity. POST `/agent/v1/results` body `{schema_version:1,machine_id,id,status,body}` returns `{accepted:true}`; response owner must equal TLS identity and persisted request machine. Polling retries redeliver the same signed request ID, not a new operation.

AgentRpcRequest is `{schema_version:1,id,machine_id,method,path,body,created_at,expires_at,dispatch_epoch,authorization:{key_id,signature}}`. Signature is detached Ed25519, base64, over UTF8 canonical JSON of the whole request without authorization. Object keys recursively sort lexicographically; arrays retain order; U+2028/U+2029 use literal backslash-u encoding; no undefined/nonfinite values. Signed fields include request ID, path, method, machine and expiry. Host checks pinned key, machine, expiry and exact path allowlist before its supervisor handles the request. Rooted file, identity, grant/fence/epoch and target checks still apply locally.

Allowed path families `/v1/health`, `/v1/operations`, `/v1/workspaces`, `/v1/roots`, `/v1/identities`, `/v1/targets`, `/v1/containers`, `/v1/services`; no arbitrary target host/address. Mutation/signing/dispatch keys stay server-side. RPC requests/results and outstanding unknown writes are retained across API/worker restart. Browser closure has no transport responsibility.

Env: `DISPATCH_SIGNING_KEY_FILE`, `DISPATCH_SIGNING_KEY_ID`; agent listener `AGENT_TLS_KEY_FILE`, `AGENT_TLS_CERT_FILE`, `AGENT_CA_CERT_FILE`, `AGENT_CA_KEY_FILE`, `AGENT_HOST`, `AGENT_PORT` (3443). Key provisioning/rotation is explicit; no per-start replacement that silently invalidates host trust.
Relay restore fence: both database restore_mode and RESTORE_MODE environment deny enqueue/claim/result acceptance. Historical epochs are quarantined. Mutations additionally require both deployment and database dispatch enabled and no maintenance; fresh GET inspection may operate while dispatch is disabled. Poll returns one envelope maximum; every frame is bounded at 96 MiB JSON. Backup maintenance may read fresh snapshots, while restore permits no remote traffic until reconciliation.
