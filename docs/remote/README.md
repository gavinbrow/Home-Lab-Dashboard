# Remote access implementation

Current strict delayed-tunnel proof and connection lifecycle evidence: [wave3](WAVE3_EVIDENCE.md). The [wave2 record](WAVE2_EVIDENCE.md) preserves its earlier test confound and pause rather than retroactively relabeling that result.

SSH uses ssh2 1.17.0. No key or password reaches a browser: connection enrollment stores an encrypted secret reference. SSH host keys must be compared out of band before enrollment and all subsequent handshakes pin the raw key's SHA-256 digest. Arbitrary browser hostnames, SSH forwarding, agent forwarding, and command proxy endpoints are absent. A terminal is explicitly a human-management account shell; its working directory does not create a project sandbox.

POST `/api/v1/remote/connections` accepts `{machine_id,kind:"ssh",config:{hostname,port,username,host_key_fingerprints:["SHA256:..."],host_key_verified_out_of_band:true},credential:{privateKey,passphrase?}}` or password instead of privateKey. Connection IDs must belong to the signed-in owner and an enrolled machine. GET the same path lists enrolled definitions without credentials. POST `/remote/connections/:id/test` verifies pinned authentication only; it does not certify identity, PTY, or SFTP behavior.

`POST /remote/connections/:id/credentials` with `{expected_version,credential}` replaces the backend's encrypted credential, increments the connection revision, revokes issued/active sessions and invalidates affected capability/SFTP/observed-desktop tests. It does not reset the upstream host's password or authorized keys. `POST /remote/connections/:id/disable` with `{expected_version}` disables new access and revokes existing sessions; historical records remain. Ticket issuance locks the current connection revision, preventing a stale request from minting an unrevoked ticket after disable or credential replacement. The UI never receives the previous secret or its reference.

POST `/api/v1/terminals` with `{connection_id}` returns `{id,ticket,expires_at,socket_path,account_scope}`. Create a WebSocket at the returned same-origin socket path using the existing HttpOnly session cookie. Send `{type:"attach",ticket}` within five seconds; tickets expire after thirty seconds and a conditional database update permits one consumption. The URL contains no ticket. Wait for `{type:"ready"}` before sending `{type:"input",data}` or `{type:"resize",cols,rows}`. Output is `{type:"output",encoding:"base64",data}`; decode to Uint8Array for xterm to preserve byte/UTF-8 boundaries. Close revokes the terminal transport; reconnect creates a new terminal and is unrelated to durable jobs.

Terminal transports close on explicit POST `/terminals/:id/revoke`, browser close, fifteen minutes without input, an eight-hour maximum, API shutdown, or failed revocation polling. Durable logout/revocation is checked every second, including pending SSH handshakes; active SSH connections are owned by the API process and die on restart. The composition must enforce WebSocket maxPayload 32768 and register @fastify/websocket before routes. Transport output buffers are bounded; slow clients are disconnected. Terminal content is never recorded in ordinary application logs or audit records.

Scoped SFTP supports an explicitly operator-provisioned OpenSSH chroot-only account after root-marker identity, known-outside-canary denial, hash round-trip and cleanup tests. Scope is the entire jail; a subdirectory of a broad account is not accepted as confinement. The actual chroot supplies the race-resistant boundary; canonical path checks are defense in depth. Windows ACL-only scope remains unavailable until a corresponding tested adapter exists. See [SFTP setup and API](SFTP.md).

The desktop gateway uses actual Apache Guacamole 1.6.0 JSON authentication and stock HTTP tunnels, with both browser WebSocket and HTTP fallback transports bound to the app session. Upstream auth tokens occur only in backend POST bodies, tunnel tokens only in backend headers; neither reaches the browser or any URL. Launch tickets are consumed atomically once for the owner and originating login. RDP keeps NLA and certificate verification enabled; clipboard/drive/SFTP transfer is disabled. JSON expiration is not used to terminate active tunnels.

Matching internal Guacamole web/guacd/JSON components and the required authoritative session-lease listener extension must be configured before launch. The extension uses documented vetoable TunnelConnectEvent and GuacamoleTunnel.close APIs. It checks the actual session before returning a tunnel and continuously closes denied upstream tunnels, including late handshakes whose UUID was never learned by the API and API outages. A fresh extension heartbeat is required before launch. No undocumented Guacamole administration endpoint is used. See [desktop deployment and API](DESKTOP.md).

Local tests (`node node_modules/tsx/dist/cli.mjs --test apps/api/src/modules/remote/*.test.ts`) cover host-key mismatch, Origin denial, ticket entropy/hash, encrypted JSON structure, active closure, SFTP traversal/canonical escape denial, actual loopback ssh2 PTY echo/resize, pending authentication/late-connect cleanup, and real PostgreSQL/HTTP/WebSocket ticket replay/session binding and active revocation. Isolated Docker fixtures additionally run actual Guacamole/guacd with Xvfb/x11vnc and an actual OpenSSH Linux chroot. These are component tests, not the user's homelab. See [current evidence](WAVE2_EVIDENCE.md). Required actual-host checks remain Windows/Linux identities and browser PTY behavior, real desktop controls/session mode/local-screen behavior, RDP certificates, and configured OS/root restrictions. No homelab machines, endpoints or credentials were supplied or guessed.

Official sources reviewed: [ssh2 1.17.0 API](https://github.com/mscdex/ssh2/tree/v1.17.0), [Guacamole 1.6.0 JSON authentication](https://guacamole.apache.org/doc/1.6.0/gug/json-auth.html), [Guacamole extension API](https://guacamole.apache.org/doc/1.6.0/gug/custom-auth.html).
